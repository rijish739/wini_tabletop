# 09 — Blind corpora (safety + PII), authored now

**What to build:** The safety and personal-data corpora, authored **now — before any detector prompt
exists** — because that is when blindness is at its maximum. They fill the corpus-integrity harness stood
up in slice 01 and gate the packages that land in slices 12–13. Authored against the taxonomy/contract
definitions, never against patterns.

**Blocked by:** 01 (the fixture schema, manifest, and integrity validator shell exist there).

**Status:** done

- [x] Corpus manifest rows added for: safety per-class (6 classes + `UNSPECIFIED_CONCERN`) + safety FP
  corpus; PII per-class (9 classes) + maths-dense precision (≥500 rows, supplied from the golden set);
  degraded-net freeze corpus; the frozen Intake input set (≥150 rows, seeded from `baseline_oracle`,
  incl. the NFKC typography, the four confident FNs, terse-real-answer, 9 nonsense probes, 42 homophones,
  a row per `ProblemCue`); the legacy-20 regression suite; the captured-STT fixtures path (replay-only).
- [x] Corpora are LLM-generated from a **written, structured grid** (class × directness × register ×
  code-switching × euphemism) — the grid is the reviewable deliverable; the integrity test **fails on any
  empty grid cell**. ≥40% indirect/euphemistic rows per safety class.
- [x] A **different generator family** for the safety and PII corpora; the integrity test asserts no
  safety/PII row was generated by the model named in `VERTEX_SAFETY_MODEL`. The LLM generates, never
  judges (scoring is exact-match against the row's label).
- [x] Every row carries `source: authored|generated:<model-id>|captured` and `grid_cell`; storage
  in-repo, public, synthetic; no row copied from production (incl. `learning_log.jsonl`).
- [x] Sign-off fields per corpus (`reviewed_by`/`reviewed_at`/`review_scope`); an unreviewed corpus may
  run under an "unreviewed" label, but no `child_safety/` cutover happens on unreviewed numbers.
